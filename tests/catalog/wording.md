# Approved wording

On-screen text that Rich has approved for rulings that change or add a message (16 November 2026). A case for one of these rulings checks these exact words. `NAME`, `LIST` and the side (front or back) stand for values the app fills in.

| Ruling | Where | Approved text |
| --- | --- | --- |
| R12 | Load edits, one amber message, a line for each part that applies | "Edits loaded." / "Saved for “NAME”; sizes match." / "Reset, not valid: LIST." / "Overlay left out; it couldn’t be read." |
| R13 | A photo arrives while a pair's other side is opening (amber) | "Wait for the other side to open, then open the photo." The export wording, "Wait for the export to finish, then open the photo.", stays for an export |
| R14, R15 | Export's note when the output is scaled down to the browser's limit | "Scaled down to fit the 16.7 MP limit." For a pair saved Separately, when it is the side not on screen: "The back is scaled down to fit the 16.7 MP limit." (or "The front…"). When both: "Both sides are scaled down to fit the 16.7 MP limit." |
| R23 | Resume, when the saved edits don't fit the stored photo (amber) | "Full edit history could not be restored, your photo has been opened fresh." (Rich's own words) |
| R24 | The six red error messages. Rich chose the short form, with no advice; the technical detail goes to the console | "Detection failed." / "Export failed." / "Copy failed." / "Share failed." / "Corner shots failed." / "Couldn’t resume." |
| R26 | Export's size line for a pair whose other side has invalid corners; Share, Download and Copy are dimmed | "Fix the back’s corners in Perspective first." (or "Fix the front’s corners…") |
| R20 | The ending of Corner shots' size line when the close-ups can't be made; both save buttons are dimmed | "· the card is too small" when that is the reason; "· fix the corners in Perspective first" for any other |
| R11 | Overlay, with invalid corners; the three logo buttons are dimmed | "Fix the corners in Perspective first." (the app's existing line) |
